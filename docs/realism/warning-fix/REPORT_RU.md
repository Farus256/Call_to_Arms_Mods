# Дополнительная проверка ИИ, предупреждений и нагрузки

Дата: 02.10.2026. Контрольная точка перед изменениями: **`9e2adba`**. Проверена установленная сборка Gates of Hell 1.067 с активными зависимостями. Исправления установлены в **ultimate_frontline_bundle**: **28 ресурсов — 3 замены и 25 новых переопределений/дополнений**.

Игру и редактор не запускали по указанию пользователя. Последний предоставленный журнал содержит завершившийся бой `3v3_wotan / battle_zones`; в нём нет `APP_ERROR` или Lua traceback. Это подтверждает завершение того боя, но не проверяет последующие изменения.

## Найдено и исправлено

| Проблема | Исправление | Ожидаемый результат |
|---|---|---|
| Frontlines после подготовки забывал старый таймер, дважды выдавал немедленный приказ и создавал вторую цепочку таймеров | `OnPrepTimeOver` вызывает одно назначение; `SetSquadOrder` сначала отменяет прежний таймер | Отряды не получают лишние конкурирующие приказы; нагрузка таймеров не удваивается |
| Повторное назначение отряду оставляло предыдущий таймер без владельца | Одна активная цепочка на отряд; проверка принадлежности callback текущему таймеру | Даже уже поставленный в очередь отменённый callback не возобновляет старый приказ |
| Удалённый отряд сначала получал приказ, затем проверялось его существование; при завершении боя оставались записи таймеров | Проверка до приказа, прекращение повторов после удаления, очистка записей при остановке | Нет повторных приказов погибшим отрядам и возобновления цепочки после завершения |
| При отсутствии подходящих подкреплений весь отбор выполнялся каждый игровой quant | Пауза повторной проверки 1 секунда через существующий механизм таймеров | Меньше повторных обходов списков; появившееся подкрепление может быть выбрано с дополнительной задержкой до 1 секунды |
| `not Cannon or not Squad` повторно применял общий множитель класса к пушкам и отделениям | Условие заменено на `and` в Battle Zones/Domination, Frontlines и Last Stand | Убраны непредусмотренные повторные штрафы к вероятности покупки этих классов |
| ПТ-пехота уже входила в `BotInfantry`, но снова прибавлялась при сравнении с общим пределом 25 | Убрано второе прибавление в трёх скриптах | Бот не считает, например, 23 бойцов с тремя ПТ-специалистами за 26 |
| `QueryScene` индексировался номером игрока; формат ответа — строки `{playerId, propCounts}` | Поиск по ID внутри строки, обработка отсутствующей строки/счётчика | Изменившийся порядок ответа не приводит к подсчёту чужих войск или обращению к `nil` |
| Стартовое предпочтение тылового флага обнуляло все закупки, если среди доступных войск не было `Aux` | Ограничение закупки действует только при наличии доступного `Aux` с положительным приоритетом | Подкрепления продолжают закупаться; сама задача захвата тылового флага сохраняется до назначения |
| Взвешенный выбор сортировал весь список ради закомментированной диагностики и определял вызывающую функцию через стек; tail call давал `Caller nil` | Линейный выбор по накопленным весам без сортировки и проверки стека | Сохраняются вероятности положительных весов; исчезает ошибочная диагностическая причина `Caller nil`. Конкретная последовательность случайных выборов может измениться |
| Семь папок папах/кубанок не содержали `ger_sidecap.mtl`, необходимый дальнему LOD | Добавлены материалы из существующих моделей, использующих побайтно тот же `ger_cockade_null.ply`, с соответствующими атласами | Устранён отсутствующий ресурс для 17 предупреждений в журнале. Проверены 21 ссылка материалов; геометрия и основные материалы головных уборов сохранены |
| У 17 DDS-текстур выбора юнитов и зимних машин отсутствовали mip-уровни | Добавлена полная цепочка уровней через официальный Microsoft DirectXTex; исходные байты основного уровня возвращены без перекодирования | Доступна штатная фильтрация при уменьшении. Формат DDS, размер основного изображения и его пиксели/BC-блоки сохранены |

Чтение неизменного лимита ожидания подкрепления также вынесено из цикла по всем кандидатам. Дополнительные постоянные обходы сцены не добавлены; существующий интервал `QueryScene(..., 5)` сохранён.

## Что проверено и сохранено

- Защита задач медиков, ремонта, экипажей, раненых, гранатчиков, дыма и ПТ-стрелков: **915 проверок** существующего обработчика приказов в четырёх режимах. Пустой маршрут и исчезновение отряда обработаны.
- Новые исправления: **18 сценариев, 67 утверждений**, включая воспроизведение прежних дефектов на исходных файлах. Проверки действующего кода без исторического источника: **11 сценариев, 45 утверждений**.
- В тесте с 1 000 вызовов `TrySpawnUnit` без доступных войск прежний код выполнял отбор 1 000 раз; новый выполняет один отбор до срабатывания секундного таймера. Это число операций в модели, **не замер FPS**.
- Синтаксис **55 эффективных Lua-файлов** проверен как Lua 5.1; исполнение сценариев — Fengari с подставным BotApi. Это не эмуляция движка GEM.
- **443 mission/include-файла**, 13 проверок регрессий типов AI-параметров: ошибок не найдено. **1 935 статических ссылок** ресурсов: отсутствующих ссылок и ошибок синтаксиса нет. Ещё 159 контекстных ссылок зависят от раскрытия макросов и учитываются отдельно.
- 17 DDS: проверены размеры и полный объём всех уровней; основной уровень сравнен побайтно. Суммарный размер этих ресурсов вырос с 12 044 304 до 16 059 836 байт, примерно на **3,83 МиБ**. Рост производительности в игре не измерялся.
- **943 файла двух установленных модов** совпадают с репозиторием по SHA-256. Из 918 прежних файлов **915 сохранены побайтно**; изменены только три Lua-файла, остальные правки добавлены новыми ресурсами.
- Новые изменения поведения находятся в Lua несюжетных режимов. Общая utility используется также Conquest; его волновая логика, экономика и интервалы штатных закупок сохранены. Визуальные исправления материалов и DDS применяются глобально.
- Сохранены ранее согласованные дистанции **90 м / 18 м**, настройки дальнего боя, КО ×2 с исключением сюжета и Conquest, построения и скрытие медицинских/снабженческих кругов.
- **Количество, время жизни, графика и настройки осколков, обломков, крови, тел и подобных объектов в этом пакете не изменены.** Текстуры частиц исключены из исправления mip-уровней. Прежние параметры накопления объектов сохранены как установлены.

## Оставшиеся предупреждения и ограничения

| Предупреждение в журнале до исправлений | Результат анализа |
|---|---|
| `No valid ev.actor` — 226 сообщений | Сообщение нативного обработчика статистики. В исследованном журнале соседствует с успешными покупками; доказательства провала покупки нет. Точная причина и безопасное исправление через Lua не установлены. Сообщение не подавлялось; Roll of Honour не отключался |
| `aimer chain ... locked` — 38 сообщений | Зарегистрированы при выходе из боя. Дефект наведения живых юнитов этим журналом не доказан; отключать наведение/контроллеры для скрытия сообщения нельзя |
| `enumerator` — 27 сообщений | Инициализация нумерации моделей с отсутствующими костями. Корректная геометрия/привязка из имеющихся файлов не установлена; фиктивные кости и удаление механизма номеров не добавлялись |
| `part6` у `blitz3_6` — 5 сообщений | Несовпадение ожидаемой части с моделью при обработке разрушенной техники. Модель и состояние обломков не изменялись, в том числе по ограничению пользователя |
| Оставшиеся `No MIP levels` | PNG частиц, две PNG динамита и служебный BMP 1×1 не конвертировались. PNG/BMP не содержат DDS-цепочек; у 1×1 нет меньшего уровня. Массовая подмена форматов и ссылок без проверки отрисовки не выполнялась |

Скрипты поиска пути, выбор конкретного укрытия, действительная видимость целей, проигрывание анимаций, загрузка исправленных материалов и баланс большого боя остаются зависимыми от движка. Статический анализ не доказывает, что все ситуации с ремонтом, медициной и боевым поведением работают безошибочно. В проверенных сценариях дополнительных ошибок не обнаружено; гарантировать всю сборку без нового боя нельзя.
